# Refactoring workflow

1. State the maintainability or performance problem and measurable goal.
2. Record existing behavior and baseline tests.
3. Define explicit non-goals; no unrelated feature changes.
4. Architect proposes incremental steps and rollback approach.
5. Refactor in small commits, preserving public behavior.
6. Run tests after each meaningful step.
7. Review API compatibility, performance, and migration implications.
8. Human reviews and approves merge/deployment.
