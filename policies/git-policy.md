# Git policy

- Never work directly on `main`, `master`, or a protected branch.
- Use descriptive task branches such as `feat/conversation-assignment`.
- Keep commits focused and explain why, not just what.
- Do not amend or rewrite shared history without approval.
- Do not force-push.
- Never commit secrets, local databases, build outputs, or customer data.
- Inspect `git status`, `git diff`, and staged diff before commit.
- Human owns merge approval and protected-branch policy.
